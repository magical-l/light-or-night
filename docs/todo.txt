优化
	✗ 1，增强“使用原生浅色模式”：先尝试用页面上自带的“浅色/深色”模式按钮。
		比扫样式表里的类名/属性难得多：要认文案（“深色”/“Dark”/“外观”）、aria-label、图标，
		还要处理“按钮藏在下拉菜单里”（bing 就是齿轮 → 外观 → 深色，两步）。而且点击是有副作用的
		动作——会写进站点的服务端偏好（cookie/账号），不像改一个 class 那样能随手撤回。
		现有的“切完复测、没变成偏好色就回滚”能挡住“点了没用”，挡不住“点错了别的东西”。
		→ 否掉。实测与理由见 docs/investigate-flip-coverage.md
	✗ 2，滤镜反转时，输入框不翻转，有边框的按钮不翻转（或者所有按钮？）
		量过：滤镜下输入框只有两档可选——和页面底同色（翻），或者纯白（不翻）。
		「不翻」拿到的是黑页面上的纯白块，比黑底黑框更糟。按钮那半同理：透明底的按钮
		「不翻」只翻得了一半（自己的边和字不翻、透出来的底还是翻的），所以「有边框的
		按钮」和「所有按钮」在这条路上没有区别。→ 否掉。
		留下的真问题：深色下「控件底 vs 页面底」那一档没生成（Radix 里 1 阶＝应用背景、
		3 阶＝元素底，本来就是两个阶），而 invert 只能给对称、抬不了这一档
		（描边对底的对比度实测 1.453:1 → 1.446:1，翻没吃掉对比度）。要解它得另立一条
		——给表单控件叠反向滤镜 + 显式补填充，本轮不做。
