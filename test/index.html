DPIB 缺陷复现测试页

这套页面用来复现 “Don't! Paint it black” 扩展的已知缺陷。纯静态、不联网、不引用外部资源（图片全部 data-URI 内联）。

三个入口各自覆盖什么

场景页 · 一个 case 一个文件

cases/

11 个独立 case 页。每页默认把同一份场景并排渲染两次：左边是「原样」（内嵌 <iframe src="?raw=1">，扩展不处理 iframe），右边是本页主体（会被扩展翻）。页面顶部有说明条（case 名 / 考什么 / 期望）与实时 DOM 状态行。

故障拷问页 · 单页分区

torture.html

§1 反向滤镜的还原度、§2 高饱和大色块的 Remap、§3 滚动条 color-scheme、§4 性能（3000 元素 + 持续变动 + rAF 帧率）、§5~§7 渐变文字 / 深色伪元素 / 深色渐变背景。页尾有逐节预期清单。

原作者的可视化难点页

test-edge-cases.html

本目录下的 test-edge-cases.html，只覆盖 Remap 的可视化难点（渐变文字、伪元素、SVG、嵌套容器等），不覆盖本目录这套缺陷。两套互补。

cases/ · 每个 case 一页：考什么、期望是什么、暴露的缺陷

点 case 名打开该页。每页左侧 iframe 是不受扩展影响的「原样」，右侧是本页真实渲染（会被扩展处理）。要看「原样」单独一页，把地址改成 ?raw=1。

「应成功 / 应判对」是扩展按设计应该做对的；「应失败」是这些页面故意要暴露的缺陷——如果它反而做对了，说明缺陷已被修复。

翻转模式矩阵（设置项，非静态 case）

扩展的「翻转模式」有 6 个取值：off / 只用原生 / 只用快速滤镜 / 只用精细 Solarized / 原生优先→滤镜 / 原生优先→精细。全局有一个默认值，单个站点可以覆盖它（还有一个「跟随全局」的选项）。

这些是设置不是页面，没法做成静态 case 页。下面这张表用于手动在 popup 里切换模式、对着各 case 页逐格验证。

模式 有原生浅色的页（如 n-nightvalue） 无原生浅色的页（如 d-nonative-media）
off 不动 不动
只用原生 切原生 不动
只用快速滤镜 上滤镜 上滤镜
只用精细 Solarized 上重映射 上重映射
原生优先→滤镜 切原生 上滤镜
原生优先→精细 切原生 上重映射

怎么跑

  1. 用 http(s) 打开，不要直接双击（file://）。最省事的做法是在本目录起一个静态服务器：
    cd test && python -m http.server 8000
    然后访问 http://localhost:8000/index.html、http://localhost:8000/cases/n-nightvalue.html、http://localhost:8000/torture.html。
  2. 或者在扩展的详情页打开「允许访问文件网址 / Allow access to file URLs」，之后就能直接双击 cases/ 里的页面打开。
  3. 为什么不能默认走 file://：扩展对 file:// 的访问默认是关闭的，content script 不会注入，页面里的缺陷也就复现不出来。同时 n-ls-odd 用 localStorage 保存主题，也需要一个正常的网页环境。
  4. 看 before / after：每个 case 页默认左右并排——左边 ?raw=1 的 iframe 是「原样」（扩展不处理 iframe），右边是本页主体、会被扩展翻。想看「原样」单独一页，把地址改成 cases/<case名>.html?raw=1（此时只有场景本体，没有说明条、没有 iframe）。
  5. 打开扩展，对每个 case 按页面顶部「期望」那一行去验证。判定组的页面本身不会变，看的是扩展是否误报/误翻。
